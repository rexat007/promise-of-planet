# وعد الكوكب — مواصفة جاهزية تكامل الصور التحريرية

**التاريخ:** 20 أكتوبر 2026  
**الحالة:** قرار مبدئي باعتماد مسار Uppy + Tiptap؛ التنفيذ غير مأذون به قبل فحص الجاهزية.

**مرجع GitHub المثبت للنسخة المرفوعة:** `afe25dd74068ae016bba7c11303f948ff146c34e`

## 1. الهدف التحريري

واجهة شبيهة بتجربة WordPress: اختيار عدة صور من الجهاز؛ استعراض وتحديد الصورة؛ اقتصاصها وتدويرها وضبط نسبتها وضغطها للويب؛ إدراجها في موضع المؤشر داخل متن الخبر؛ تعديل عرضها ومحاذاتها والتفاف النص حولها مع سلامة RTL/LTR؛ تعيين صورة رئيسية منفصلة للخبر؛ إرفاق تعليق توضيحي ومصدر وحقوق استخدام؛ وإعادة فتح المسودة دون فقد العناصر.

## 2. حلول مفتوحة المصدر مناسبة

| الجزء | الاختيار المبدئي | حقيقة تقنية وحدود |
|---|---|---|
| اختيار الملفات ولوحة الصور | `@uppy/core`, `@uppy/dashboard`, `@uppy/react` | واجهة جاهزة قابلة للدمج في React؛ لا تعني وجود مكتبة صور دائمة. |
| الاقتصاص/التدوير/التكبير/القلب | `@uppy/image-editor` | يعمل مع Dashboard، ولا يكفي وحده لتحرير الصور داخل المقال. |
| تقليل حجم الصور | `@uppy/compressor` | ضغط في المتصفح، مع اختبار واقعي للجودة والحجم واتجاه الصورة. |

## 3. وضع المصدر الذي تحققنا منه

- `src/components/news/editor/RichTextEditor.tsx` و`src/components/news/editor/tiptapExtensions.ts` يوجدان في GitHub. **وجود المكوّن لا يثبت أنه مستخدم فعليًا داخل محرر الخبر في مساحة Studio**؛ يجب تتبع الاستدعاء الحالي محليًا.
- `src/types/richNewsDocument.ts` و`functions/src/shared/richNewsDocumentContract.ts` يحصران عناصر المستند الغني في أنواع نصية/قوائم، ولا يجيزان `image` حاليًا.
- `src/services/richNewsTiptapAdapter.ts` يحقق في بنية المستند؛ إدخال Image مباشرة دون تحديث متسق للعقد سيفشل أو يتسبب بفقد البيانات.
- `src/components/news/PublicNewsHub.tsx` في GitHub يعرض النص العام وصورة الغلاف، دون إثبات عرض صور مدمجة في المتن.
- `src/types/news.ts` و`functions/src/news/newsRepository.ts` يحفظان `featuredImage` في صورته الحالية كرابط نصي؛ ليس نظام مكتبة أصول ولا إثبات حقوق.
- قواعد `storage.rules` في GitHub تسمح بمسارات الشعار ومرفقات صحافة المواطن فقط؛ **لا يوجد نشر عام لصور الأخبار**.
- الأرشيف القديم `وعد-الكوكب-promise-of-planet.zip` يحتوي في `src/components/admin/ArticleEditor.tsx` محررًا يدعم زر `image` وحقل رابط صورة بارزة؛ لا يظهر فيه نظام معالجة أو مخزن صور صحفية متكامل. المرجع لإلهام السلوك، لا للنسخ غير المشروط.

## 4. الحد المعماري غير القابل للتجاوز

1. لا نغيّر نسخة المستند أو نضيف عقدة `image` من الواجهة فقط: يجب تحديث العقد المشترك والعميل والخادم والاختبارات والعرض العام في وحدات منفصلة ومترابطة.
2. يجب أن تشير عقدة الصورة إلى أصل إعلامي معتمد `assetId` وخصائص تقديم آمنة، لا إلى Blob محلي دائم أو `data:` Base64 أو رابط غير موثوق.
3. بيانات التعليق البديل والمصدر والحقوق مستقلة عن تنسيق العرض؛ المصادقة على الحقوق قبل الإتاحة العامة قرار بشري.
4. صورة الغلاف قد تستخدم نفس الأصل الموجود في المتن، لكن اختيارها مستقل ولا يتطلب رفع نسخة مزدوجة.
5. التفاف النص يتطلب سياسة RTL/LTR واضحة ومحاذاة محدودة، وتتحول الصور الجانبية إلى عرض متجاوب مناسب للهاتف دون خروج أفقي.
6. لا يُستخدم Firebase `getDownloadURL()` لتجاوز مسار تخزين خاص قبل قرار نشر وتصميم بوابة إتاحة عامة آمنة.
7. لا تعديل على الأخبار الحقيقية ولا اختلاق صور/سجلات منشورة للتجربة.
8. لا تثبيت حزم أو تحديث lockfile أو صلاحيات Firebase دون إذن ونطاق معتمدين.

## 5. وحدة الجاهزية التالية — IMG-F0 (Read-only)

**قائمة سماح الكتابة:** فارغة.

التحقق من النسخة المحلية في Studio:
- ربط `AdminNewsManagement.tsx` بالمحرر الغني الفعلي وحالة الحفظ/إعادة الفتح.
- مخطط عقد rich documents وطرق التحقق والنسخ؛ واختبار إمكانية إضافة عقدة صورة دون كسر السجلات القديمة.
- نسخة الحزم المثبتة محليًا وأي Uppy/Tiptap Image موجود أصلًا، وملف القفل المعتمد.
- كيفية عرض المتن عند القراء، RTL/LTR واستجابة الجوال.
- مسارات Storage المتاحة، أثر الـPublic token URLs، وجود workflow معتمد لنشر `storage.rules` (فحص فقط).
- حدود حل أصغر نموذج تجريبي معزول لا يُجري أي اتصال Firebase، ولا يعدل المسودات.

**نتيجة إلزامية:** تقرير بالمسارات والتوابع والتبعيات الغائبة والمخاطر؛ اقتراح نطاق وحدة تجريبية واحدة مع قائمة سماح مقترحة (لا تنفيذ).

## 6. مراحل البناء بعد قرار جديد

- **IMG-F1 — نموذج مستقل غير متصل بالشبكة:** تجربة Uppy Dashboard/Image Editor/Compressor مع صورة يختارها المستخدم محليًا، ثم إدراج ومعاينة داخل Tiptap دون حفظ سحابي. لا تثبيت إلا بعد اعتماد حزم/نسخ/مسارات محددة.
- **IMG-F2 — عقد مستند الصور:** عقدة صورة آمنة ومراجع أصول، تحقق عميل وخادم، تحويلات إصدار وتوافق تاريخي واختبارات round-trip.
- **IMG-F3 — مكتبة أصول وحقوق وصلاحيات:** تخزين خاص، سياسة حقوق، اختيار غلاف، مراجعة/حذف آمن، مسار نشر قواعد Firebase عبر GitHub Actions منفصل.
- **IMG-F4 — الواجهة المتكاملة:** محرر الخبر، تحديد صورة الغلاف، ترتيب الصور داخل النص، caption/alt/credit، عرض عام متجاوب، اختبارات UX بالعربية والإنجليزية.

كل وحدة: مواصفة دقيقة ← برومبت محدود ← تحقق ← مراجعة بصرية ← قبول صريح ← التالي. تتراكم ملفات Markdown الإضافية وتُراجع مرة واحدة قبل الـPush؛ لا تنظيف متكرر.

## 7. شروط التوقف

STOP بلا كتابة عند اختلاف بنية RichNews الحالية عما هو مفترض، أو غياب ترخيص متوافق، أو حاجة لنطاق أوسع من الملفات المتفق عليها، أو عدم القدرة على التحقق من مسار تحميل آمن للصور، أو تعديل/حذف غير مقصود في GitHub Sync.
